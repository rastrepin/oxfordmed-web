# Архітектура oxfordmed-web

## Стек
- Статичні HTML-сторінки (без React, без Next.js)
- Тонкий шар JS — модалка форми, експанд-блоки, FAQ-аккордеон
- Vercel serverless functions для /api/leads/oxfordmed
- Аналог стеку onclinic-web

## Чому статичний HTML
- Швидкість (немає React-bundle, миттєва hydration)
- Простота — Cowork генерує HTML за шаблоном
- Vercel роздає статику з CDN — оптимально для мобільного трафіку (~80%)
- Менше можливих багів ніж у React-додатку

## Як додати нову сторінку
1. Контент-чат пише MD-файл у /content/oxford-med/[city]/[slug].md
2. Cowork генерує HTML за шаблоном (поки вручну, потім — build-скрипт)
3. HTML кладеться в /lviv/[slug]/index.html
4. Запис у data/services.js (коли буде створено) — або руками в плитки хабу
5. Push у dev → QA-чат перевіряє → merge в main

## Чому МОЖЛИВО НЕ Next.js на майбутнє
Якщо Oxford розшириться на Київ і інші міста — оцінимо чи варто
переходити на Next.js з MD-парсером і serviceMap-driven сторінками.
Поки кількість сторінок невелика — статичний HTML дає кращий
баланс швидкість/складність.
